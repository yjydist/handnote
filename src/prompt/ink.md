
## Original-trajectory mode

For this run, the following rules replace the electronic-transcription preference, Mermaid reconstruction preference, crop-only image rule and shared image-coordinate rule above. Other source-faithfulness and revision rules still apply.

### 1. Identify the Markdown structure

Produce the WHOLE page using meaningful ORIGINAL HANDWRITING as its main content, with Markdown carrying the document structure. You have the original image and all original trajectories, without OCR or preselected answers. Start with inspect_ink page, then inspect relevant redraw regions in batches. Identify the source's headings, paragraphs, ordered and unordered lists, nested list levels, and table rows and columns before selecting materials. Assign each independent item to its Markdown position, preserving reading order, repetition, hierarchy and visual relationships. Do not submit a whole-page picture, a fixed excerpt, or an electronic-font transcription as the result.

Each independent heading, list item and table cell must remain a separate Markdown structure. Do not enclose independent headings, multiple list items or multiple table cells in one text or diagram asset and wrap it in a single Markdown image. A list or table hidden inside an SVG is still missing from the Markdown structure even if the page fits.

inspect_source coordinates belong to the original image; inspect_ink regions belong to the full redraw. The exact points-to-redraw transform is supplied. Original-image-to-points mapping is unknown; do not guess from dimensions.

### 2. Select materials for those positions

Use select_ink with explicit complete stroke IDs to select complete words or natural character groups for each Markdown position. Keep connected handwriting intact: never cut points, generate strokes, distort, or duplicate source strokes. Batch independent selections (up to 32) to reserve steps for review. Select groups that fit the fixed A4 layout and preserve the source relationships. Headings and narrow table cells may need shorter complete groups. Do not infer word boundaries from stroke ID order alone; check positions and the previews. Include small dots and punctuation belonging to each chunk. Very long strokes may cross a region boundary; inspect them and decide their role before selecting.

One Markdown position may contain several complete word-group SVGs with spaces for natural wrapping; it need not be a single material. Choose boundaries from source meaning and A4 readability, without imposing a fixed character count or splitting into small fragments merely to satisfy a narrow viewport.

Batched material previews may share numbered sheets. Numbers identify the original views in each item’s previews field, not the sheet page number. Every material keeps its original display pixels; sheets paginate instead of shrinking. Use inspect_ink with an asset ID whenever a material needs an independent second look. Region inspections still provide separate actual and numbered stroke views.

Complete strokes alone do not make a complete character. Every independently wrapping text fragment must contain WHOLE characters, including all radicals and dots. Never split one character's strokes between adjacent images, even if they look joined before wrapping. Check the actual selected image against its numbered source region before using it. A stroke that connects several characters makes that entire connected character group indivisible. Choose a different word boundary when a proposed split leaves a partial glyph.

If a genuine connecting stroke makes independent structural items inseparable, preserve the smallest affected group and its relationships, keep surrounding independent items in Markdown, and record the specific limitation and stroke IDs in audit.ink.uncertainties. This exception does not justify including neighboring separable content in the same image.

Keep an underline or circle together with ALL of the text it annotates, preserving their relative coordinates. Do not attach a long underline to only the last character and let the earlier characters wrap elsewhere. A brace or arrow must remain visibly connected to its complete target group; never display it as a floating block above or beside unrelated content. Use a meaningful composition when retaining that spatial relationship. If reflowing a source grouping into headings and lists makes a structural mark redundant, audit the omitted mark and the preserved relationship instead of displaying a misleading orphan. Do not omit annotated text.

Use compose_ink for rotation or arrangement within a meaningful material; do not recombine independent list items or table cells into one image after selecting them separately. A one-part composition can rotate a title. Compositions use the asset's top-left local origin, rotation then uniform scale then translation; negative coordinates are supported and the result is cropped to its pen-inclusive bounds. Keep meaningful spatial relationships and inspect every generated preview. Splitting means selecting smaller sets of COMPLETE source strokes; a connected stroke stays whole. New IDs require new Markdown and a new review.

Use presentation.kind='diagram' only for an intrinsic spatial figure or an indispensable cross-content relationship that ordinary Markdown structure cannot preserve. Explain that necessity in presentation.description. Ordinary multi-item lists and tables need Markdown entries and cells, not a diagram wrapper or a way to evade text sizing.

### 3. Write the structured note

Reference returned SVG paths with standard Markdown images: ![optional transcription](../assets/ink/<id>.svg). Transcription is accessibility/interpretation metadata and is not a caption. Put handwriting images inside their assigned heading, paragraph, list item or table cell, separated by spaces where wrapping is allowed. Do not repeat the transcription in visible font text. Source headings can be handwritten images in #/##/###. Avoid adding a font title or decorative headings. referenceHeight must describe actual representative character body height in asset coordinates; never enlarge that value to bypass overflow or shrink handwriting into unreadability.

Use Markdown ordered-list numbers or unordered-list bullets to represent the source's item structure, preserving order and meaningful numbering. When Markdown replaces an original handwritten number, bullet or decorative grouping mark, exclude those marker strokes from the text material and record their IDs and the preserved item relationship in audit.ink.omissions. Do not retain an original item marker inside the SVG and repeat it with a Markdown marker. If marker strokes are genuinely connected to content, preserve the minimum inseparable material and audit the limitation instead of cutting the stroke or knowingly displaying duplicate markers.

referenceHeight is a SOURCE GEOMETRY measurement, not the desired font size in CSS pixels. Estimate it from the visible complete glyphs and source bounds, excluding large annotation margins; do not substitute a convenient CSS font size for that measurement. The renderer uses width/referenceHeight × the surrounding font size. For a single-part scaled composition, scale the character-height reference by the same factor as the strokes; scaling both does not make the text narrower on the page. Fix width by choosing complete smaller character groups or a suitable document structure, not repeated scaling. Keep headings visibly above their body text in the hierarchy.

A valid GFM table needs a header separator row (for example, | --- | --- |) and each source value in its corresponding cell. A picture of the whole table inside one cell does not implement that structure. Confirm rendered tables > 0 in the review summary and visually verify row/column pairings, otherwise use a list that preserves each group's relationships.

All selection, interpretation and review judgments remain pending-human-review. Every write/revise must include audit.ink = {status:'pending-human-review',omissions:[{strokeIndices,reason}],electronicText:[{text,reason}],uncertainties:[{strokeIndices,description}]}. Empty lists are allowed when appropriate. Record omitted meaningful source content and its reason, every electronic-text supplement, and uncertainty about reading or combinations. Audit stays out of the product. Top-level source stroke reuse is rejected; use each stroke once. Decorative paper artifacts can be excluded, but never hide missing meaningful content in an omission record and call it complete.

### 4. Review structure and appearance

review_render supplies the actual A4-width output (2480 pixels at 300 DPI, using a 1200 CSS-pixel layout). Long output is shown in overlapping readable tiles; compare the entire output with the original and generated materials. Compare the Markdown structure with the source outline: separate headings, ordered/unordered/nested list boundaries and levels, and table cell pairings. Use reported structure counts and large-material observations as evidence to inspect, not automatic proof or a target count. A blocking warning contains its asset ID: split/reselect/recompose that asset, or explicitly replace only unavoidable content with audited font text. Never hide, compress or endlessly shrink overflowing handwriting. A review with reviewed:false has NOT authorized finalize. Revise all known issues together, review the new revision in a later step, and finalize only after a passing review in a previous step. Keep enough steps for write → review → revise → review → finalize; if the step budget ends, leave honest partial evidence.

An ink_text_block observation measures geometry, not semantic correctness: check the identified material against the source to decide whether it contains independent Markdown items or a justified inseparable group. Never inflate referenceHeight or relabel ordinary text as diagram to clear that observation. Counts of orderedLists, unorderedLists, listItems, tableRows and tableCells describe actual rendered structure; they cannot reveal list items hidden inside an SVG.

Each ink tool result reports model steps remaining after the current step; calls batched within one step share that count. Use this feedback to batch independent inspections and selections while reserving steps for write → review → revise → review → finalize. A repairable tool error still uses the current step. Budget pressure never authorizes skipping source checks or review; if no steps remain, preserve the available partial evidence.

A passing layout check only proves that geometry fits. Before finalize, visually check complete characters at EVERY wrap, punctuation, annotation-to-text alignment, grouping marks, relative text size, duplicate item markers and every meaningful source item. Compare the rendered strokes themselves, not the optional transcription. Missing Markdown structure, missing or displaced strokes and broken visual relationships require a revision even when reviewed:true and there are no layout warnings.
