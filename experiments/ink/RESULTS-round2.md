## 本轮解决的具体问题

完整来源行或句子必须先有唯一精确对应，内部片段才可绑定。短行“聚落”不再因为是目标“聚落类型”的前缀而复用，第二轮第 70 页自动笔迹覆盖因此降为零。所有 OCR 行，包括没有可用笔迹的行，都参与重复实例判断。代码、公式、图片、硬换行、水平分隔线、定义列表及折叠详情不再拼成虚假的连续来源上下文。

OCR 框继续作为定位证据，来源行完整正文笔画的可见框作为共享度量。目标字体加载后测量“国田目中”的可见高度及下伸量。第 69 页自动标题“天气”使用相同笔画 0–7，1200px 输出中 PNG 布局高度由 29.36px 变为 43.45px；不再按带留白的 67 源单位 OCR 框缩小。报告保存实际字体测量值、源单位/em、基线和输出边界。

共享度量不会把每个片段都变大。第 69 页定义行的小“天气”原本就小于同行正文，统一缩放仍保留这个差异。第 2 页正文也不会被强行归一成普通字体宽高；第 70 页地形条件行在 720px 输出中仍明显细小，片段布局框约 17.45px 高，其中包含倾斜和起伏，不能视作真实单字高度。是否合适仍需人工视觉核验。

## Agent 与应用边界

七个工具的模型名称、说明、schema 和模型媒体格式归 Agent；应用处理器接收只读步骤上下文，继续拥有检查缓存、图片授权、revision/review/finalize 事务。`@handnote/agent` 从内存源图、提示词、预算、模型配置、处理器和事件接收器运行，不依赖应用目录、RunStore 或 SessionRecorder。

模型事件按“更新 Agent 会计 → 应用保存已知快照 → 记录原事件 → 等待 manifest 更新 → 后续请求”执行。事件写失败保留已取得 usage，原始错误从 Agent 传播，不进入 Provider 网络重试。SDK 同步诊断由应用脱敏写入 stderr；循环结束后关闭迟到回调，已有业务或持久化 fatal 不再误记为 Provider stream error。

应用源码、运行存储、恢复、CLI 和评测协调位于 `apps/handnote`。根 `src/cli.ts`、`scripts/real-eval.ts` 与提示词路径兼容，跨单元调用使用公开包入口。迁目录时业务源码逐文件字节相同，未升级历史 run 格式。
