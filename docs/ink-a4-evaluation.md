## 人工失败与修复方向

第 2 页优化版用 5 张 SVG 表达内容，其中只有 1 个 Markdown 标题、1 个无序列表、3 个列表项；多项原始编号内容仍藏在 SVG 内部。人工审查明确否决这种大块选材。布局没有阻塞警告、成功 finalize 或较高笔画覆盖率，都不代表语义结构正确。

另发现列表圆点落在多行 SVG 底部，已由 `d52cce8` 修复并加入失败回归。这只修正渲染对齐，无法替代选材粒度改进。

`cd72f07` 要求 Markdown 承担标题、段落、独立列表项、嵌套层级与表格单元格；每个位置可包含多个完整字词 SVG，自然换行。由 Markdown 替代的手写编号或结构标记要记录省略笔画与保留关系，避免重复标记。真实连笔与必要批注关系保留最小不可分组，不切字、不切笔；普通列表不能改称 diagram 来规避拆分。

对旧稿只读重新编译时，新增诊断找出 3 张分别高约 6.21、5.59、8.17 个参考字高的文本素材。提示是非阻塞的检查线索：它不能判断 SVG 内部语义，也不会自动识别被标为 diagram 的普通列表。原 run、原图、审计和修订记录保持原样；诊断单独保存于 `runs/ink-a4-comparison-20260909/page-2-semantic-diagnostics.json`。

原成品使用 953/954 笔画，省略笔画 757 位于轨迹底边且审计为孤立点。离线检查没有发现该页④的拆字或重复笔画，但不足以弥补结构失败；第 69、70 页及已有“区”案例仍需视觉验证。后续应逐项检查完整字、漏笔、重复内容、编号、批注归属、表格配对与可读性。模型判断继续保留 `pending-human-review`。
